# BONGO Secure Rewards Portal

بوابة مكافآت عربية RTL مبنية على FastAPI، مصممة لتتكامل مع مزوّد دفع مستضاف.

## قرار أمني غير قابل للتفاوض

- لا يوجد حقل لإدخال PAN أو تاريخ الانتهاء أو CVV.
- لا يقبل API بيانات البطاقة ولا يسجل بيانات الدفع.
- لا تحفظ البوابة بيانات الاتصال المقدمة في نموذج العرض.
- الدفع يتم في صفحة HTTPS مستضافة لدى مزوّد دفع معتمد؛ لا تستخدم رابطاً عشوائياً أو صفحة وسيطة.
- لا تضع مفاتيح API أو أسرار المزود في Git.

## التشغيل

```bash
cd secure_rewards_portal
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 8000
```

افتح `http://127.0.0.1:8000`، وفحص الصحة عبر `/health`.

## ربط مزوّد الدفع

هذه النسخة لا تنشئ جلسة دفع تلقائياً. قبل الإنتاج، أضف تكاملاً خلفياً مع SDK الرسمي لمزوّد معتمد:
1. أنشئ جلسة Checkout من الخادم باستخدام مبلغ/عملة/معرّف طلب موثوق من قاعدة البيانات.
2. أعد رابط الجلسة المؤقت الذي يصدره المزود، لا رابطاً ثابتاً من مدخل المستخدم.
3. تحقق من توقيع Webhook، ومنع إعادة تشغيل الأحداث (idempotency).
4. لا تمرر PAN أو CVV إلى هذا التطبيق مطلقاً.
5. لا تعتبر عودة المتصفح دليلاً على نجاح الدفع؛ اعتمد webhook الموقّع فقط.

متغير `REWARDS_CHECKOUT_URL` في هذه النسخة مخصص لبيئة اختبار/عرض فقط، ولا يغني عن إنشاء جلسة دفع ديناميكية موثوقة.

## الاختبارات

```bash
pytest -q
```

لا تنشر الخدمة على الإنترنت قبل إضافة HTTPS، وتحديد المعدل، ومراقبة إساءة الاستخدام، وسياسة خصوصية واحتفاظ واضحة، وربط مزود الدفع واختبار webhooks.
